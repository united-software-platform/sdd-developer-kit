## Context

Мотивация — в [`proposal.md`](./proposal.md), требования — в
[`specs/readme-badges/spec.md`](./specs/readme-badges/spec.md).

Существенные для решения факты текущего состояния:

- Версии инструментов закреплены как `ARG` в `Dockerfile`: `UV_VERSION=0.12.7` (объявлен до `FROM`),
  `OPENSPEC_VERSION=1.11.0`, `PYTHON_VERSION=3.12`. Базовый образ задан строкой
  `FROM ghcr.io/united-software-platform/claude:latest`.
- Версия kit'а лежит в файле `VERSION` в корне (`1.0.0`), лицензия — в `LICENSE` (MIT).
- `origin` репозитория — `github.com/united-software-platform/sdd-developer-kit`.
- В репозитории нет пайплайнов CI и нет публикации образа в реестр: бейджей статуса сборки или
  версии опубликованного образа взять неоткуда.
- `README.md` — файл проекта, в поставку kit'а (`tools/install/`) не входит.

## Goals / Non-Goals

**Goals:**

- Один источник истины на значение: бейдж читает `Dockerfile` или `VERSION`, а не копию значения.
- Блок бейджей не требует ни CI, ни дополнительных файлов конфигурации в репозитории.
- Ограничения решения (публичность репозитория, привязка к `main`) зафиксированы там, где их
  увидит следующий разработчик.

**Non-Goals:**

- Не показывается версия CLI Claude Code: базовый образ закреплён тегом `latest`, версии в
  репозитории нет, и её выяснение потребовало бы правки `Dockerfile`.
- Не закрепляется тег базового образа вместо `latest` — это отдельное решение о воспроизводимости
  сборки, а не задача оформления `README.md`.
- Не добавляются бейджи статуса сборки и покрытия: пайплайнов нет.
- Не заводится проверка синхронности бейджей и `Dockerfile`: при динамических значениях
  рассинхрона по построению не возникает.

## Decisions

### Динамические бейджи shields.io вместо статических значений

Каждый бейдж версии — это `img.shields.io/badge/dynamic/regex`: shields скачивает файл по
переданному `url`, применяет регулярное выражение `search` и подставляет в бейдж результат
`replace`. Источники читаются как raw-файлы GitHub с ветки `main`.

Почему не статические бейджи с вписанным значением: значение в `README.md` — вторая копия
версии, которая расходится с `Dockerfile` при первом же обновлении инструмента, и расхождение
ничем не обнаруживается. Почему не проверочный скрипт в `tools/`: он лечит симптом (расхождение
двух копий) вместо причины (наличие второй копии) и добавляет обязательный шаг в процесс правки
`Dockerfile`.

Общая форма URL:

```text
https://img.shields.io/badge/dynamic/regex?url={raw-url}&search={regex}&replace=$1&label={label}
```

Значения параметров `url` и `search` percent-кодируются целиком: в них есть `:`, `/`, `=`, `+`
и скобки, а незакодированный `&` разорвал бы строку запроса.

`{raw-url}` для `Dockerfile`:
`https://raw.githubusercontent.com/united-software-platform/sdd-developer-kit/main/Dockerfile`,
для версии kit'а — тот же префикс с `/VERSION`.

Состав бейджей (в порядке размещения):

| Бейдж | Файл-источник | `search` (до кодирования) | `label` |
|-------|---------------|---------------------------|---------|
| Базовый образ | `Dockerfile` | `FROM (ghcr\.io/\S+/claude:\S+)` | `claude image` |
| Python | `Dockerfile` | `ARG PYTHON_VERSION=([\d.]+)` | `python` |
| OpenSpec | `Dockerfile` | `ARG OPENSPEC_VERSION=([\d.]+)` | `openspec` |
| uv | `Dockerfile` | `ARG UV_VERSION=([\d.]+)` | `uv` |
| Версия kit'а | `VERSION` | `([\d.]+)` | `version` |
| Лицензия | — (статический бейдж `license-MIT`) | — | `license` |

Регулярное выражение базового образа захватывает имя вместе с тегом: по решению пользователя бейдж
отвечает на вопрос «какой Claude» ссылкой на образ и его тег, а не версией CLI.

### Бейдж лицензии — статический

Лицензия меняется исключением, а не итерацией, и `LICENSE` — не структурированный источник, из
которого имя лицензии извлекается устойчивым регулярным выражением. Статический
`img.shields.io/badge/license-MIT-blue` проще и не ломается от переформатирования текста лицензии.
Ссылка бейджа ведёт на `./LICENSE` относительным путём: исключение
[DOC-015](../../../rules/documentation-rules.md#ссылки-doc-015) распространяется на URL
изображения, но внутренние цели ссылок остаются относительными.

### Ссылки бейджей

- Бейдж базового образа → страница пакета в GHCR (внешняя цель, абсолютный URL).
- Бейджи Python, OpenSpec, uv → `./Dockerfile` относительным путём: значение приходит оттуда,
  и читателю нужен именно этот файл.
- Бейдж версии kit'а → `./VERSION`, бейдж лицензии → `./LICENSE`.

### Описание состава — в `README.md`, не в `docs/sdd-kit.md`

Первоначально перечень «бейдж ↔ источник значения» планировался в `docs/sdd-kit.md` как в документе
об окружении и его версиях. При реализации выяснилось, что `docs/sdd-kit.md` перечислен в
`PAYLOAD_PATHS` установщика (`tools/install/install.sh`) и копируется в каждый целевой проект:
раздел про бейджи репозитория `sdd-developer-kit` оказался бы в чужом проекте, где эти бейджи
не существуют, а ссылки ведут на посторонний репозиторий.

Поэтому описание живёт в `README.md` — файле, которому принадлежит сам блок бейджей и который
в поставку не входит. Раздел размещается в конце документа, перед версионированием: он нужен тому,
кто правит `Dockerfile`, а не читателю первого экрана.

## Risks / Trade-offs

- **Репозиторий недоступен анонимно** → `raw.githubusercontent.com` вернёт `404`, и все пять
  динамических бейджей отрисуются как ошибка. Проверяется первой задачей реализации; если
  репозиторий приватный, бейджи версий делаются статическими, а расхождение с `Dockerfile`
  фиксируется в `README.md` как принятое ограничение.
- **Регулярное выражение привязано к тексту `Dockerfile`** → переименование `ARG` или изменение
  формы строки `FROM` ломает бейдж. Смягчение: соответствие «бейдж ↔ `ARG`» описано в
  `README.md`; поведение при поломке выбрано «видимая ошибка», а не «старое значение» —
  молча устаревший бейдж хуже сломанного.
- **Бейджи показывают состояние `main`** → на ветке с ещё не влитой правкой `Dockerfile` бейдж
  покажет прежнюю версию. Принимается: `README.md` в `main` — то, что видит внешний читатель.
- **Зависимость от внешнего сервиса** → недоступность `img.shields.io` (офлайн, корпоративный
  фильтр) оставляет вместо бейджей alt-текст. Поэтому alt-текст каждого бейджа называет
  характеристику, а не служебное слово `badge`, и остаётся читаемым сам по себе.
- **Кеширование shields** → после правки `Dockerfile` бейдж обновляется не мгновенно.
  Функционально безразлично, специальных мер не требует.

## Migration Plan

1. Проверить, доступен ли `raw.githubusercontent.com/.../sdd-developer-kit/main/Dockerfile`
   анонимно. При `404` — перейти на статические значения и зафиксировать ограничение.
2. Добавить блок бейджей в `README.md`, описать его состав отдельным разделом там же, обновить
   навигацию и таблицу версий документа.

### Результат проверки (задачи 1.1–1.2)

Репозиторий доступен анонимно: `raw.githubusercontent.com/.../main/Dockerfile` отдаёт `200`, и все
четыре регулярных выражения по `Dockerfile` извлекают ожидаемые значения
(`ghcr.io/united-software-platform/claude:latest`, `3.12`, `1.11.0`, `0.12.7`). Переход на
статические значения не потребовался.

Отдельно: `.../main/VERSION` отдаёт `404`. Причина не в видимости репозитория — файл `VERSION`
отслеживается git локально, но соответствующий коммит ещё не выгружен в `origin/main`. Решение:
бейдж версии остаётся динамическим — он начнёт отдавать `1.0.0` сразу после push ветки в `main`,
и заменять его статическим значением ради временного состояния незачем. До push бейдж показывает
`resource not found`, что соответствует выбранному поведению «видимая ошибка вместо устаревшего
значения».

Ещё одно наблюдение: `img.shields.io` отвечает `403` на запросы с user-agent по умолчанию у
`urllib`; при проверке бейджей из скриптов требуется браузерный `User-Agent`. На отрисовку в
GitHub и в редакторах Markdown это не влияет.

Откат: удалить из `README.md` блок бейджей, раздел о их составе и пункт навигации — документ
возвращается к текущему состоянию, других файлов изменение не затрагивает.
