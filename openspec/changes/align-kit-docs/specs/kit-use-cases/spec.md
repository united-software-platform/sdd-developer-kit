## Purpose

Описывает документ кейсов репозитория kit'а: где он лежит, как пользователь набора находит его
из `README.md`, какие задачи за пределами основного пути он покрывает и какие сведения об образе
окружения агента в нём допустимы.

## ADDED Requirements

### Requirement: Расположение документа кейсов
Репозиторий kit'а SHALL вести документ кейсов в `docs/use-cases.md`. `README.md` SHALL называть его
ссылкой в разделе «Куда дальше». Документ MUST NOT входить в состав поставки: он описывает работу
с kit'ом, а не с проектом, в который kit установлен.

#### Scenario: Пользователь ищет задачу за пределами основного пути
- **WHEN** пользователь прошёл шаги `README.md` и ищет, как решить задачу, которой в шагах нет
- **THEN** раздел «Куда дальше» `README.md` ведёт его в `docs/use-cases.md`

#### Scenario: Установка kit'а в проект
- **WHEN** kit устанавливается в целевой проект установочным скриптом
- **THEN** `docs/use-cases.md` в целевой проект не попадает

### Requirement: Состав кейсов
Документ кейсов SHALL содержать кейс для каждой из задач:
- прочитать установщик до запуска;
- установить конкретную ревизию kit'а или установить его без сети;
- работать под несколькими аккаунтами;
- обновить образ окружения;
- закрепить образ окружения;
- запустить агента на собственной сборке образа;
- дать агенту запускать цели `make` через host-runner;
- обновить kit в проекте.

#### Scenario: Пользователь закрепляет образ
- **WHEN** пользователь хочет зафиксировать образ окружения в проекте
- **THEN** он находит в документе кейсов кейс закрепления образа с переменными закрепления
  и значением каждого тега

#### Scenario: Пользователь обновляет kit
- **WHEN** пользователь повторно устанавливает kit в проект, где тот уже стоит
- **THEN** кейс обновления kit'а объясняет сверку с манифестом, обновление инструментов SDD
  и судьбу целей и файлов, выведенных из поставки

### Requirement: Переменные сценария в кейсе
Переменную окружения, которую пользователь задаёт только для одного сценария, SHALL называть кейс
этого сценария вместе с её назначением. Это относится к переменным закрепления и подстановки образа
и к переменным канала host-runner.

#### Scenario: Пользователь настраивает host-runner
- **WHEN** пользователь настраивает канал к целям `make` на хосте
- **THEN** кейс host-runner называет переменные порта, адреса и токена раннера с их назначением

#### Scenario: Пользователь подставляет свою сборку образа
- **WHEN** пользователь хочет запускать агента на собственном образе
- **THEN** кейс собственной сборки называет переменную имени образа

### Requirement: Сведения об образе в кейсах
Кейсы об образе окружения агента SHALL ограничиваться тем, что наблюдает пользователь: откуда
берётся образ, что означает каждый тег, как закрепить образ или подставить свою сборку, что
происходит без сети. События пересборки, состав пайплайна и проверка перед публикацией MUST NOT
входить в документ кейсов.

#### Scenario: Пользователь читает кейс обновления образа
- **WHEN** пользователь открывает кейс обновления образа окружения
- **THEN** он находит команду обновления и поведение без сети, а описания событий пересборки
  в кейсе нет

#### Scenario: Разработчик ищет события пересборки
- **WHEN** разработчик самого набора ищет, по каким событиям пересобирается образ
- **THEN** он находит их в документе для разработчиков, а не в документе кейсов
