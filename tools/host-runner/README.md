# Раннер целей сборки на хосте

Позволяет агенту в контейнере запускать цели `make` окружения проекта, не получая доступа
к Docker-сокету: агент отправляет по HTTP имя цели из белого списка, раннер выполняет её
на хосте и возвращает вывод с кодом возврата.

## Зачем это нужно

В контейнере агента нет ни `make`, ни `docker`: рабочее дерево смонтировано внутрь, а сборка
и управление контейнерами остаются на хосте. Без раннера агент не может ни поднять окружение,
ни проверить результат своей правки в `docker-compose.yml` или `Makefile` — он видит только
исходники.

Раннер закрывает этот разрыв узким каналом: одна цель `make` из фиксированного перечня вместо
доступа к Docker-сокету, который дал бы контейнеру полный контроль над хостом.

---

## Как это устроено

| Сторона | Компонент | Роль |
|---------|-----------|------|
| Хост | [runner.py](./runner.py) | HTTP-сервер: принимает `GET /run/{цель}`, выполняет `make {цель}` в корне репозитория |
| Контейнер агента | [call.sh](./call.sh) | Клиент на `wget`: отправляет запрос с токеном, печатает вывод, переносит код возврата |

Docker и `make` остаются на хосте. Контейнер агента получает только текст вывода — ни сокета,
ни привилегий, ни возможности выполнить произвольную команду.

---

## Установка

1. Проверить, что в `.env` заданы `AGENT_RUNNER_TOKEN`, `AGENT_RUNNER_PORT` и `AGENT_RUNNER_URL`.
   Если токена нет — сгенерировать:

```bash
echo "AGENT_RUNNER_TOKEN=$(head -c 24 /dev/urandom | base64 | tr -d '/+=' | cut -c1-32)" >> .env
```

2. Дать контейнеру агента имя `host.docker.internal`. На Linux оно не резолвится само —
   сервису `claude` в `docker-compose.yml` нужен `extra_hosts`:

```yaml
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

3. Пересоздать контейнер агента — переменные `AGENT_RUNNER_*` приезжают через `env_file: .env`:

```bash
docker compose --profile claude up -d --force-recreate claude
```

> **Внимание:** `.env` в репозиторий не коммитится (`.gitignore`), поэтому токен на каждой машине
> задаётся заново. Общего значения по умолчанию у него нет и быть не должно.

---

## Запуск

Из корня репозитория, в отдельном терминале на хосте:

```bash
set -a && . ./.env && set +a
python3 tools/host-runner/runner.py
```

Раннер печатает каталог, адрес и белый список целей, а затем — каждый входящий запрос.
Без `AGENT_RUNNER_TOKEN` он не стартует; без `Makefile` в рабочем каталоге — тоже.

> **Внимание:** раннер читает `.env` один раз, при старте, и держит значения в своём
> окружении. Для `docker compose` переменная окружения приоритетнее файла, поэтому после
> любой правки `.env` раннер нужно перезапустить — иначе цели `make` будут выполняться
> со старыми значениями, а файл будет выглядеть корректным.

Переменные настройки:

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `AGENT_RUNNER_TOKEN` | — (обязательна) | Общий секрет; сравнивается в постоянном времени |
| `AGENT_RUNNER_PORT` | `11900` | Порт прослушивания |
| `AGENT_RUNNER_BIND` | `0.0.0.0` | Интерфейс прослушивания |
| `AGENT_RUNNER_WORKDIR` | корень репозитория | Каталог, в котором выполняются цели |
| `AGENT_RUNNER_TIMEOUT` | `900` | Предел выполнения одной цели, секунды |

---

## Использование агентом

```bash
tools/host-runner/call.sh up
tools/host-runner/call.sh logs
```

Цели `authors` и `scan` принимают параметры в виде присваиваний `ПЕРЕМЕННАЯ=значение`:

```bash
tools/host-runner/call.sh authors REPO=/путь/к/проекту
tools/host-runner/call.sh scan REPO=/путь/к/проекту CODE_PATH=src AUTHOR='Иванов Иван'
```

Присваивания уходят одной строкой url-safe base64 в параметре `args`: значения содержат
пробелы и кириллицу, а собирать процентное кодирование в `bash` пришлось бы посимвольно.

Ответ:

```text
exit: 0
--- stdout ---
…
--- stderr ---
…
```

Ненулевой `exit` цели даёт ненулевой код возврата клиента — неуспех виден вызывающему.

---

## Границы доступа

- **Белый список целей** задан в `runner.py` константой `ALLOWED_TARGETS` и повторяет цели
  `Makefile` репозитория: `init`, `up`, `down`, `restart`, `logs`, `authors`, `scan`. Любое
  другое имя отклоняется с кодом 400.
- **Ни shell, ни произвольные аргументы:** команда собирается как список
  `["make", цель, присваивания…]` и выполняется без интерпретатора команд, поэтому
  подстановка через имя цели невозможна.
- **Белый список переменных** задан константой `TARGET_PARAMETERS` и действует отдельно для
  каждой цели. Цель, которой в нём нет, вызывается без параметров: присваивание для неё
  отклоняется, а не игнорируется — иначе опечатка в имени переменной выглядела бы как
  успешный прогон.
- **Значения проверяются разрешающим образцом** (`PARAMETER_PATTERNS`), а не перечнем
  запрещённых символов. Это обязательное условие: значение подставляется в рецепт `make`
  и попадает в порождаемый им `shell`, поэтому одинарная кавычка в `IDENTITY` или `AUTHOR`
  была бы выходом из кавычек и выполнением произвольной команды на хосте. Кавычка, `# Раннер целей сборки на хосте

## Границы доступа

,
  обратная кавычка, `;` и перевод строки в образцы не входят.
- **Один запуск за раз:** сервер однопоточный, параллельных `make` не бывает.
- **Все запросы логируются** в консоль раннера — видно, что именно запросил агент.

> **Внимание:** `AGENT_RUNNER_BIND` по умолчанию `0.0.0.0` — порт доступен всем, кто может
> дойти до хоста по сети, и защищён только токеном. В недоверенной сети ограничьте его
> адресом шлюза Docker-сети либо правилом межсетевого экрана.

> **Внимание:** цели белого списка меняют состояние окружения: `up` и `down` поднимают
> и останавливают контейнеры, `init` дополнительно тянет образы и создаёт каталоги данных.
> Раннер расширяет права агента ровно на этот перечень — расширять список стоит осознанно.

> **Внимание:** `authors` и `scan` раздвигают границу за пределы репозитория. Путь `REPO`
> ограничен только образцом, поэтому агент может попросить снять слепок любого каталога хоста,
> к которому у раннера есть доступ, а результат прочитать в `snapshot/`. Образец защищает
> от выполнения произвольной команды, но не от чтения постороннего репозитория. Если это
> нежелательно — ограничьте `REPO` конкретным корнем в `PARAMETER_PATTERNS`.

> **Внимание:** каталог результатов у `scan` общий для всех проектов. Прогон монтирует
> `SNAPSHOT_DIR` целиком и получает доступ на запись к слепкам всех снятых проектов, а не
> только текущего. Имя проекта в путь добавляет сам агент, поэтому каталог результатов
> его не содержит. Нужна жёсткая граница — задавайте отдельный `SNAPSHOT_DIR` под проект.

> **Примечание:** данные ArangoDB лежат в bind-монтировании `./data/arangodb`, а `make down`
> тома не удаляет — ни одна цель белого списка не приводит к потере данных. Это свойство
> текущего `Makefile`, а не раннера: добавление цели вида `reset` его отменит.
