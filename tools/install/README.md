# Установщик SDD Developer Kit

Разворачивает инструменты SDD Developer Kit в каталоге целевого проекта: копирует состав поставки
в корень проекта, предупреждает о перезаписи существующих файлов и записывает манифест установки.

## Зачем это нужно

Kit применяется не только к самому себе. Чтобы использовать его инструменты в продуктовом проекте,
файлы окружения, правил и SDD-инструментов должны оказаться в корне этого проекта. Раньше это был
ручной перенос по памяти: состав определялся каждый раз заново, версия перенесённого набора нигде
не фиксировалась, а перезапись существующих файлов проекта ничем не предупреждалась.

---

## Использование

Скрипт запускается из клона kit'а и принимает каталог целевого проекта:

```bash
./tools/install/install.sh /path/to/project
```

Источником файлов служит сам клон, поэтому состав поставки всегда соответствует версии kit'а,
из которой запущен скрипт. Целевой каталог должен существовать и быть доступен на запись.

---

## Режимы запуска

| Ключ | Поведение |
|------|-----------|
| (без ключей) | Интерактивный режим: при конфликтах выводится перечень и запрашивается подтверждение |
| `-n`, `--dry-run` | Предварительный просмотр: выводится полный план, не записывается ни один файл |
| `-y`, `--yes` | Неинтерактивный режим: перезапись разрешена заранее, вопрос не задаётся |
| `-h`, `--help` | Справка по использованию |

Без терминала и без `--yes` установка при обнаружении конфликтов завершается ошибкой, а не
перезаписывает файлы молча.

## Состав поставки

| Компонент | Пути |
|-----------|------|
| Окружение агента | `Dockerfile`, `docker-compose.yml`, `Makefile`, `.env.example` |
| Правила репозитория | `rules/`, `CLAUDE.md`, `AGENTS.md` |
| Инструменты SDD | `.claude/skills/`, `.claude/commands/`, `openspec/config.yaml` |
| Раннер целей сборки | `tools/host-runner/` |
| Документ окружения | `docs/sdd-kit.md` |

Перечень задан в скрипте явным списком, а не выведен из `.gitignore`: граница поставки не совпадает
с границей версионирования. Если путь из списка отсутствует в клоне kit'а, установка прерывается
ошибкой — молчаливый пропуск сделал бы состав поставки зависящим от состояния клона.

Файлы ложатся в корень целевого проекта по тем же относительным путям, по которым лежат в kit'е,
и после установки принадлежат проекту: дорабатывать их — штатный сценарий.

---

## Что не переносится

- `openspec/changes/` и `openspec/specs/` — рабочие артефакты самого kit'а;
- `README.md` — описывает kit как продукт; описание окружения для проекта ставится
  отдельным файлом `docs/sdd-kit.md`;
- `tools/install/` — установщик нужен в клоне kit'а, а не в целевом проекте;
- `.env`, каталог SSH-ключей, каталог профилей аккаунтов, `data/`, служебные каталоги git —
  локальные данные машины и секреты.

---

## Как обнаруживаются конфликты

Установка выполняется в два прохода. Первый строит план и не пишет ничего, второй записывает файлы
после подтверждения. Каждый файл поставки попадает в одну из трёх категорий:

| Категория | Условие | Требует подтверждения |
|-----------|---------|-----------------------|
| Создание | В целевом проекте файла нет | Нет |
| Обновление | Файл есть, его контрольная сумма совпадает с записанной в манифесте — установлен kit'ом и не менялся | Нет |
| Перезапись | Файл есть, но его контрольная сумма не совпадает с манифестом либо манифеста нет | Да |

При отказе от подтверждения установка завершается, не записав и не удалив ни одного файла.

## Манифест установки

Успешная установка записывает в корень целевого проекта `.sdd-kit-manifest.json`:

```json
{
  "kit_version": "1.0.0",
  "installed_at": "2026-09-08T10:54:09Z",
  "files": [
    {"path": "Dockerfile", "sha256": "…"}
  ]
}
```

Манифест пишется последним шагом, поэтому его отсутствие или неполнота — признак незавершённой
установки. По нему определяются версия установленного kit'а и перечень его файлов без обращения
к репозиторию kit'а, а при повторном запуске — какие файлы изменены проектом.

Версия берётся из файла `VERSION` в корне kit'а, а не из истории git: клон может быть получен
архивом без истории.

---

## Коды возврата

| Код | Значение |
|-----|----------|
| `0` | Установка выполнена либо выведен план в режиме предварительного просмотра |
| `1` | Ошибка (нет целевого каталога, отсутствует путь поставки, нет подтверждения) или отказ пользователя |

## Ограничения

- **Слияния файлов нет.** Конфликт разрешается перезаписью целиком: цели `Makefile` или разделы
  `CLAUDE.md` целевого проекта установщик не сливает с поставкой. Слияние выполняется вручную
  после установки.
- **Сбой во втором проходе оставляет проект частично установленным.** Транзакционного отката нет;
  признак незавершённой установки — отсутствующий или неполный манифест, лечение — повторный запуск.
- **Готового к запуску окружения установка не даёт.** `.env` заполняется вручную из `.env.example`,
  SSH-ключ и профиль аккаунта создаются отдельно — порядок описан в
  [`docs/sdd-kit.md`](../../docs/sdd-kit.md).
- **Пути поставки без пробелов.** Список путей разбирается построчно, а манифест — простым
  разбором строк; пробелы в именах файлов поставки не поддерживаются.
- **Обновление и откат не реализованы.** Манифест создаёт для них основу, но повторный запуск
  выполняет установку заново, а не обновление.
