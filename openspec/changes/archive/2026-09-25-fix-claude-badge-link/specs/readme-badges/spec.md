## MODIFIED Requirements

### Requirement: Разметка блока бейджей
Блок бейджей SHALL оформляться штатным Markdown вида `[![alt](url-изображения)](url-ссылки)`;
HTML в нём MUST NOT использоваться, что сохраняет запрет
[DOC-005](../../../rules/documentation-rules.md#разметка-markdown). Ссылка бейджа, ведущая на
файл внутри репозитория, MUST быть относительной; абсолютный URL допускается только там, где цель
действительно внешняя.

Ссылка бейджа SHALL вести на носитель или проект той характеристики, которую бейдж называет: бейдж
версии компонента, закреплённой в файле репозитория, — на этот файл; бейдж компонента, разрешаемого
при сборке, — на репозиторий или проект, где этот компонент выпускается; бейдж лицензии — на файл
лицензии. Ссылка MUST NOT вести на артефакт самого репозитория kit'а — его страницу пакета, реестр
образов или сам `README.md`, — когда бейдж называет не kit, а входящий в него компонент: читатель
нажимает на бейдж, чтобы уйти к источнику характеристики, и возврат на тот же набор ответа не даёт.

Цель ссылки MUST NOT зависеть от того, откуда бейдж берёт значение: носитель значения выбирается
способом закрепления версии, а цель ссылки — принадлежностью характеристики, и служебная ветка
носителя целью ссылки не становится.

#### Scenario: Бейдж лицензии
- **WHEN** бейдж лицензии ведёт на файл `LICENSE` в репозитории
- **THEN** его ссылка записана относительным путём, а абсолютный URL остаётся только у изображения
  бейджа

#### Scenario: Каждый бейдж имеет alt-текст
- **WHEN** изображение бейджа не загрузилось
- **THEN** на его месте отображается alt-текст, называющий характеристику и файл-источник её
  значения — само значение в alt-текст не выносится, иначе оно стало бы ручной копией версии

#### Scenario: Читатель нажимает бейдж выпуска Claude Code
- **WHEN** читатель нажимает бейдж, показывающий выпуск Claude Code в опубликованном образе
- **THEN** он попадает в репозиторий базового образа, где этот выпуск закрепляется, а не на страницу
  пакета образа самого kit'а

#### Scenario: Бейдж компонента ведёт на артефакт kit'а
- **WHEN** ссылка бейджа, называющего версию входящего в набор компонента, ведёт на страницу пакета
  образа kit'а, его реестр или сам `README.md`
- **THEN** это считается нарушением: бейдж называет компонент, а ссылка возвращает читателя к набору

#### Scenario: Значение бейджа приходит из служебной ветки
- **WHEN** значение бейджа читается из файла служебной ветки носителя разрешённых версий
- **THEN** ссылка бейджа всё равно ведёт на проект или репозиторий компонента, а не на эту ветку

### Requirement: Документирование состава и источников
Репозиторий kit'а SHALL описывать состав блока бейджей, источник значения и цель ссылки каждого
бейджа, чтобы при правке `Dockerfile` или `VERSION` было видно, какие бейджи затрагиваются, а при
правке ссылки — куда она обязана вести. Описание SHALL размещаться в документе для разработчиков
самого набора: адресат описания — тот, кто правит источники значений, а не пользователь набора.
Описание MUST NOT размещаться в документах, входящих в поставку kit'а: блок бейджей принадлежит
этому репозиторию, и в установленном проекте такое описание было бы неверным. Ограничения блока —
зависимость от публичной доступности репозитория и привязка значений к ветке `main` — MUST быть
зафиксированы явно по [DOC-020](../../../rules/documentation-rules.md#полнота-содержания).

Перечень целей ссылок, допускаемых исключением
[DOC-015](../../../rules/documentation-rules.md#ссылки-doc-015), SHALL совпадать с фактическими
ссылками блока: цель, на которую не ссылается ни один бейдж, в перечне MUST NOT оставаться.

Сам блок бейджей SHALL оставаться в `README.md` между заголовком файла и назначением: он показывает
пользователю состояние набора, и его размещение этим требованием не меняется.

#### Scenario: Разработчик правит Dockerfile
- **WHEN** разработчик собирается переименовать `ARG` в `Dockerfile`
- **THEN** он находит в документе для разработчиков набора перечень бейджей, зависящих от этого `ARG`

#### Scenario: Разработчик проверяет цель ссылки бейджа
- **WHEN** разработчик открывает описание блока бейджей, чтобы понять, куда ведёт ссылка бейджа
- **THEN** цель ссылки каждого бейджа названа там наравне с источником его значения

#### Scenario: Пользователь читает README
- **WHEN** пользователь набора открывает `README.md`
- **THEN** он видит блок бейджей, а описания их источников и ограничений в документе нет

#### Scenario: Установка kit'а в целевой проект
- **WHEN** kit устанавливается в другой проект установочным скриптом
- **THEN** описание блока бейджей в состав поставки не попадает

#### Scenario: Репозиторий закрыт для анонимного доступа
- **WHEN** репозиторий недоступен анонимно и источники значений не читаются
- **THEN** ограничение зафиксировано в документации как известное, а бейджи версий заменяются
  статическими значениями

#### Scenario: Ссылка на страницу пакета больше не используется
- **WHEN** ни один бейдж блока не ведёт на страницу пакета образа kit'а
- **THEN** страница пакета в перечне допустимых целей ссылок не упоминается
