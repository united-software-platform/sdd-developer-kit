- [x] 1.1 Привести `ARG OPENSPEC_VERSION` в `Dockerfile` к виду, принимающему версию извне (значение
      по умолчанию сохраняется для локальной сборки); проверка — `docker build --build-arg OPENSPEC_VERSION=1.11.0 .`
      собирается, а `openspec --version` в собранном образе выводит переданное значение
- [x] 1.2 Создать `.github/workflows/docker-agent.yml` с заданием `resolve`: вычисление имени образа
      из координат репозитория в нижнем регистре, чтение версии kit'а из `VERSION`, разрешение версии
      OpenSpec по мажорному диапазону; проверка — запуск `workflow_dispatch` печатает все три значения
      в выводе задания, версия OpenSpec принадлежит закреплённой мажорной
- [x] 1.3 Добавить задание `check` с матрицей `linux/amd64` и `linux/arm64`: сборка под одну платформу,
      запуск `id`, `git --version`, `openspec --version`, `python3 --version`, `uv --version` от пользователя
      образа и сверка версии OpenSpec с рассчитанной в `resolve`; проверка — задание падает, если подставить
      в сверку заведомо неверную версию, и проходит на фактической
- [x] 1.4 Добавить задание `push`: сборка мультиарх-манифеста из кэша заданий проверки, теги «версия kit'а»
      и `latest` (последний — только для основной ветки), публикация в GHCR встроенным токеном; проверка —
      после запуска в реестре присутствуют оба тега, а `docker manifest inspect` показывает обе архитектуры
- [x] 1.5 Ограничить права: `contents: read` в `resolve` и `check`, `packages: write` только в `push`;
      публикация отключена для события `pull_request`; проверка — запуск пайплайна на запросе слияния
      выполняет проверку и пропускает задание публикации
- [x] 1.6 Настроить триггеры: `push` и `pull_request` с path-фильтром (`Dockerfile`, `VERSION`, файл пайплайна),

      коммит, меняющий только документацию, пайплайн не запускает, а коммит в `Dockerfile` запускает
