## 4. Сквозная проверка

- [x] 4.1 Пройти порядок установки целиком в чистом каталоге: установка → `make init` → `make up` →
  `make shell`; внутри контейнера `openspec --version` и версия из `OPENSPEC_VERSION` совпадают,
  команды `/opsx:*` доступны
- [x] 4.2 Проверить сценарий смены версии: изменить `OPENSPEC_VERSION` в `Dockerfile`, пересобрать
  образ, выполнить `make openspec-init` и убедиться, что skills и команды обновились, а `openspec/changes`
  и `openspec/specs` не изменились

  Закрыта по косвенным данным (решение пользователя, две пересборки образа не выполнялись):
  задачей 4.1 подтверждено, что `openspec init` исполняется внутри контейнера и версия утилиты там
  совпадает с `OPENSPEC_VERSION` из `Dockerfile` (1.11.0), а прогоном `make init` на репозитории kit'а —
  что повторный запуск переустанавливает skills и команды, сохраняя `openspec/config.yaml`,
  `openspec/changes/` и `openspec/specs/`. Непроверенным остался сам факт смены версии образа.
