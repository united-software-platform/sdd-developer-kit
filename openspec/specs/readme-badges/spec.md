# readme-badges Specification

## Purpose

Описывает блок бейджей `README.md`: какие характеристики репозитория он обязан показывать, из каких
файлов репозитория берутся их значения и какими средствами разметки блок оформляется, чтобы
читатель узнавал состав окружения с первого экрана, а значения не расходились с источниками.

## Requirements

### Requirement: Обязательный состав блока бейджей
`README.md` SHALL содержать блок бейджей, показывающий шесть характеристик репозитория: базовый
Claude-образ вместе с его тегом, версию Python, версию OpenSpec, версию uv, версию kit'а и лицензию.
Блок MUST располагаться между заголовком файла и назначением.

Блок SHALL оставаться единственным местом `README.md`, где показываются номера версий: перечень
состава инструментов версий не приводит и ссылается на этот блок, поэтому второй копии значений
в документе не возникает.

Абсолютные URL, допускаемые в блоке по
[DOC-015](../../../rules/documentation-rules.md#ссылки-doc-015), MUST NOT считаться единственным
исключением этого правила в `README.md`: второе место — названия пунктов перечня состава
инструментов, где ссылка ведёт на внешний источник инструмента. Размещение самого блока при этом
не меняется.

#### Scenario: Читатель открывает README
- **WHEN** читатель открывает `README.md` и видит первый экран
- **THEN** ему видны базовый образ с тегом, версии Python, OpenSpec и uv, версия kit'а и лицензия —
  без перехода в `Dockerfile`, `VERSION` или `LICENSE`

#### Scenario: Блок размещён после назначения
- **WHEN** блок бейджей размещён ниже назначения или в другом разделе `README.md`
- **THEN** размещение считается нарушением: для самого блока исключение DOC-015 действует только
  между заголовком и назначением

#### Scenario: Версия понадобилась в другом разделе
- **WHEN** раздел `README.md` говорит об инструменте, у которого есть бейдж версии
- **THEN** раздел ссылается на блок бейджей или на файл-источник, а номер версии в свой текст
  не выносит

### Requirement: Значения бейджей связаны с источниками в репозитории
Значения бейджей базового образа, Python, OpenSpec, uv и версии kit'а SHALL вычисляться из файлов
репозитория — `Dockerfile` для образа и трёх версий инструментов, `VERSION` для версии kit'а.
Эти значения MUST NOT дублироваться в `README.md` вручную: изменение версии в источнике меняет
бейдж без правки `README.md`.

Бейдж версии kit'а SHALL показывать номер с префиксом `v` — единообразно с git-тегом релиза, которому
эта версия соответствует. Префикс SHALL добавляться при отображении бейджа: файл `VERSION` остаётся
источником значения и хранит номер без префикса, поэтому смена версии MUST NOT требовать правки
`README.md`.

#### Scenario: Обновление версии инструмента
- **WHEN** в `Dockerfile` меняется значение `ARG PYTHON_VERSION`, `ARG OPENSPEC_VERSION` или
  `ARG UV_VERSION`
- **THEN** соответствующий бейдж показывает новое значение, а `README.md` не редактируется

#### Scenario: Смена базового образа
- **WHEN** в `Dockerfile` меняется строка `FROM` базового Claude-образа или её тег
- **THEN** бейдж образа показывает новое имя образа вместе с новым тегом

#### Scenario: Источник значения переименован
- **WHEN** `ARG` в `Dockerfile` переименован или удалён и значение перестаёт извлекаться
- **THEN** бейдж отображается как ошибка, а не как устаревшее значение — расхождение видно, а не
  замаскировано

#### Scenario: Инкрементация версии kit'а
- **WHEN** файл `VERSION` меняется с `1.0.0` на `1.1.0`
- **THEN** бейдж версии показывает `v1.1.0`, совпадая с меткой тега `v1.1.0`, а `README.md` не
  редактируется

### Requirement: Разметка блока бейджей
Блок бейджей SHALL оформляться штатным Markdown вида `[![alt](url-изображения)](url-ссылки)`;
HTML в нём MUST NOT использоваться, что сохраняет запрет
[DOC-005](../../../rules/documentation-rules.md#разметка-markdown). Ссылка бейджа, ведущая на
файл внутри репозитория, MUST быть относительной; абсолютный URL допускается только там, где цель
действительно внешняя.

#### Scenario: Бейдж лицензии
- **WHEN** бейдж лицензии ведёт на файл `LICENSE` в репозитории
- **THEN** его ссылка записана относительным путём, а абсолютный URL остаётся только у изображения
  бейджа

#### Scenario: Каждый бейдж имеет alt-текст
- **WHEN** изображение бейджа не загрузилось
- **THEN** на его месте отображается alt-текст, называющий характеристику и файл-источник её
  значения — само значение в alt-текст не выносится, иначе оно стало бы ручной копией версии

### Requirement: Документирование состава и источников
Репозиторий kit'а SHALL описывать состав блока бейджей и источник значения каждого бейджа, чтобы
при правке `Dockerfile` или `VERSION` было видно, какие бейджи затрагиваются. Описание SHALL
размещаться в документе для разработчиков самого набора: адресат описания — тот, кто правит
источники значений, а не пользователь набора. Описание MUST NOT размещаться в документах, входящих
в поставку kit'а: блок бейджей принадлежит этому репозиторию, и в установленном проекте такое
описание было бы неверным. Ограничения блока — зависимость от публичной доступности репозитория
и привязка значений к ветке `main` — MUST быть зафиксированы явно по
[DOC-020](../../../rules/documentation-rules.md#полнота-содержания).

Сам блок бейджей SHALL оставаться в `README.md` между заголовком файла и назначением: он показывает
пользователю состояние набора, и его размещение этим требованием не меняется.

#### Scenario: Разработчик правит Dockerfile
- **WHEN** разработчик собирается переименовать `ARG` в `Dockerfile`
- **THEN** он находит в документе для разработчиков набора перечень бейджей, зависящих от этого `ARG`

#### Scenario: Пользователь читает README
- **WHEN** пользователь набора открывает `README.md`
- **THEN** он видит блок бейджей, а описания их источников и ограничений в документе нет

#### Scenario: Установка kit'а в целевой проект
- **WHEN** kit устанавливается в другой проект установочным скриптом
- **THEN** описание блока бейджей в состав поставки не попадает

#### Scenario: Репозиторий закрыт для анонимного доступа
- **WHEN** репозиторий недоступен анонимно и источники значений не читаются
- **THEN** ограничение зафиксировано в документации как известное, а бейджи версий заменяются
  статическими значениями
