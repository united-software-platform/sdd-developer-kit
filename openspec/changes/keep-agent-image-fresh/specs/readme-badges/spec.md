## MODIFIED Requirements

### Requirement: Обязательный состав блока бейджей
`README.md` SHALL содержать блок бейджей, показывающий шесть характеристик репозитория: выпуск
Claude Code в опубликованном образе окружения, версию Python, версию OpenSpec, версию uv, версию kit'а
и лицензию. Блок MUST располагаться между заголовком файла и назначением.

Бейдж Claude Code SHALL называть конкретный выпуск, а не подвижную ссылку, по которой базовый образ
получен: читатель открывает `README.md`, чтобы узнать, что он получит в контейнере, и слово `latest`
на этот вопрос не отвечает.

Блок SHALL оставаться единственным местом `README.md`, где показываются номера версий: перечень
состава инструментов версий не приводит и ссылается на этот блок, поэтому второй копии значений
в документе не возникает.

Абсолютные URL, допускаемые в блоке по
[DOC-015](../../../rules/documentation-rules.md#ссылки-doc-015), MUST NOT считаться единственным
исключением этого правила в `README.md`: второе место — названия пунктов перечня состава
инструментов, где ссылка ведёт на внешний источник инструмента. Размещение самого блока при этом
не меняется.

#### Scenario: Читатель открывает README
- **WHEN** читатель открывает `README.md` и видит первый экран
- **THEN** ему видны выпуск Claude Code, версии Python, OpenSpec и uv, версия kit'а и лицензия —
  без перехода в `Dockerfile`, `VERSION` или `LICENSE`

#### Scenario: Бейдж показывает подвижную ссылку
- **WHEN** бейдж Claude Code показывает `latest` или иную подвижную ссылку вместо номера выпуска
- **THEN** это считается нарушением: характеристика не раскрыта, хотя бейдж присутствует

#### Scenario: Блок размещён после назначения
- **WHEN** блок бейджей размещён ниже назначения или в другом разделе `README.md`
- **THEN** размещение считается нарушением: для самого блока исключение DOC-015 действует только
  между заголовком и назначением

#### Scenario: Версия понадобилась в другом разделе
- **WHEN** раздел `README.md` говорит об инструменте, у которого есть бейдж версии
- **THEN** раздел ссылается на блок бейджей или на файл-источник, а номер версии в свой текст
  не выносит

### Requirement: Значения бейджей связаны с источниками в репозитории
Значение бейджа SHALL вычисляться из того носителя в репозитории, который хранит истинную версию
компонента, и MUST NOT дублироваться в `README.md` вручную: изменение версии в источнике меняет бейдж
без правки `README.md`.

Носитель определяется тем, как версия компонента закрепляется:

- версии компонентов, закреплённых полностью, — интерпретатора Python и менеджера пакетов uv —
  SHALL браться из `Dockerfile`: там они и назначаются;
- версия kit'а SHALL браться из файла версии репозитория;
- версии компонентов, разрешаемых в момент сборки, — выпуска Claude Code и утилиты OpenSpec — SHALL
  браться из носителя, который обновляет пайплайн публикации образа.

Значение, записанное в `Dockerfile`, MUST NOT быть источником бейджа для компонента, разрешаемого
при сборке: для базового образа `Dockerfile` хранит подвижную ссылку, а для утилиты OpenSpec —
значение по умолчанию локальной сборки, закреплённое лишь мажорным разрядом. В обоих случаях
записанное в `Dockerfile` расходится с содержимым опубликованного образа, причём второе выглядит
достоверным номером версии, и расхождение не заметно читателю.

Носитель разрешённых версий SHALL обновляться публикацией образа, а не человеком: значение рождается
при сборке, и ручное обновление разошлось бы с образом при первой же пересборке.

Бейдж версии kit'а SHALL показывать номер с префиксом `v` — единообразно с git-тегом релиза, которому
эта версия соответствует. Префикс SHALL добавляться при отображении бейджа: файл `VERSION` остаётся
источником значения и хранит номер без префикса, поэтому смена версии MUST NOT требовать правки
`README.md`.

#### Scenario: Обновление версии инструмента
- **WHEN** в `Dockerfile` меняется значение `ARG PYTHON_VERSION` или `ARG UV_VERSION`
- **THEN** соответствующий бейдж показывает новое значение, а `README.md` не редактируется

#### Scenario: Смена базового образа
- **WHEN** в `Dockerfile` меняется строка `FROM` базового Claude-образа
- **THEN** бейдж Claude Code показывает выпуск из образа, опубликованного после этой правки, —
  значение берётся из носителя разрешённых версий, а не из строки `FROM`

#### Scenario: Пересборка образа принесла новый выпуск Claude Code
- **WHEN** образ пересобран и опубликован с новым выпуском Claude Code
- **THEN** бейдж Claude Code показывает этот выпуск, а `README.md` и `Dockerfile` не редактируются

#### Scenario: Пересборка образа принесла новый выпуск OpenSpec
- **WHEN** образ пересобран и опубликован с новым выпуском утилиты OpenSpec в пределах закреплённого
  мажорного разряда
- **THEN** бейдж OpenSpec показывает этот выпуск, а не значение по умолчанию из `Dockerfile`

#### Scenario: Значение по умолчанию в Dockerfile отличается от опубликованного
- **WHEN** `ARG OPENSPEC_VERSION` в `Dockerfile` содержит версию, отличную от находящейся
  в опубликованном образе
- **THEN** бейдж показывает версию из опубликованного образа, и расхождение не попадает
  в `README.md`

#### Scenario: Источник значения переименован
- **WHEN** носитель значения переименован или удалён и значение перестаёт извлекаться
- **THEN** бейдж отображается как ошибка, а не как устаревшее значение — расхождение видно, а не
  замаскировано

#### Scenario: Инкрементация версии kit'а
- **WHEN** файл `VERSION` меняется с `1.0.0` на `1.1.0`
- **THEN** бейдж версии показывает `v1.1.0`, совпадая с меткой тега `v1.1.0`, а `README.md` не
  редактируется
