## Why

Образ окружения агента сейчас собирается локально в каждом проекте, куда установлен kit: `docker-compose.yml`
ссылается на тег `claude-openspec:local`, которого нет ни в одном реестре, поэтому шаг `make build` обязателен
и занимает минуты на установку глобального пакета npm и интерпретатора Python. Работа при этом повторяется:
`Dockerfile` один и тот же во всех проектах, а результат сборки у каждого свой и ничем не подтверждён — ни
воспроизводимости, ни проверки того, что собранный образ вообще работоспособен.

Сборка образа — задача репозитория kit'а, а не каждого установленного проекта. Организация уже собирает так
базовый образ `ghcr.io/united-software-platform/claude`: пайплайн проверяет обе архитектуры и публикует
мультиарх-образ в GHCR. Тот же приём убирает локальную сборку из установки: проект получает готовый
проверенный образ загрузкой из реестра.

## What Changes

- **BREAKING** `Dockerfile` выводится из состава поставки: он остаётся исходником образа в репозитории kit'а,
  а в целевые проекты не копируется. Локальная сборка образа в установленном проекте становится невозможной
  и не требуется.
- **BREAKING** Цель `make build` удаляется. Отдельной цели получения образа не заводится: образ приходит
  при запуске контейнера целью `make up`.
- **BREAKING** Из белого списка host-runner удаляется цель `build`: цели, которой нет в `Makefile`, в белом
  списке быть не может.
- В репозиторий добавляется пайплайн GitHub Actions, собирающий образ окружения агента для `linux/amd64`
  и `linux/arm64`, проверяющий каждую архитектуру запуском инструментов образа и публикующий проверенный
  мультиарх-образ в GHCR под именем `ghcr.io/united-software-platform/sdd-developer-kit`.
- Образ пересобирается по расписанию, а не только при изменении `Dockerfile`: обновления базового образа
  `claude` и новые выпуски инструментов приходят из внешних источников, а не из коммитов репозитория, и
  push-триггером не ловятся. Версия OpenSpec перестаёт быть жёстко закреплённой третьим разрядом и
  разрешается при сборке в пределах закреплённой мажорной версии — иначе плановая пересборка выдавала бы
  тот же состав инструментов и смысла бы не имела.
- Каждая сборка проверяет фактические версии инструментов в образе и останавливает публикацию при
  расхождении с ожидаемыми: плановая пересборка идёт без участия человека, и непроверенный образ иначе
  попал бы в реестр под тем же тегом, что и рабочий.
- `docker-compose.yml` в поставке ссылается на опубликованный образ вместо локального тега и теряет секцию
  `build`. Имя образа и тег выносятся в переменные окружения: значение по умолчанию задаёт поставка,
  пользователь может закрепить конкретный тег в `.env`.
- Порядок установки в `README.md` сокращается на шаг сборки: после `make init` и заполнения `.env` следующий
  шаг — `make up`.

## Capabilities

### New Capabilities

- `agent-image`: публикация образа окружения агента — имя образа и схема тегов, поддерживаемые архитектуры,
  обязательная проверка образа до публикации, события пересборки (включая плановую) и политика обновления
  версий инструментов, разграничение прав пайплайна, а также требования к потреблению опубликованного
  образа в установленном проекте (закрепление тега, поведение при недоступности реестра).

### Modified Capabilities

- `kit-installation`: из состава поставки исключается `Dockerfile`; требование «операции окружения выполняются
  целями make» перестаёт называть сборку образа среди операций окружения и описывает получение образа из
  реестра.
- `host-runner`: белый список целей приводится к фактическому составу `Makefile` — без `build`.
- `repo-bootstrap`: шаг бутстрапа «сборка образа» заменяется получением опубликованного образа; требование
  о независимости SSH-ключей от образа сохраняется, но формулируется через опубликованный образ.

## Impact

- Новые файлы: `.github/workflows/` — пайплайн сборки и публикации образа. Каталога `.github/` в репозитории
  сейчас нет; незаархивированный change `add-repo-versioning` планирует добавить туда же проверку версии,
  и его утверждение «первый пайплайн в репозитории» после этого изменения перестаёт быть верным — файлы
  пайплайнов независимы и не конфликтуют.
- Изменяемые файлы: `docker-compose.yml` (образ из GHCR вместо локальной сборки), `Makefile` (удаление цели
  `build`), `.env.example` (переменные имени и тега образа), `install.sh` (`PAYLOAD_PATHS` без `Dockerfile`),
  `README.md` (порядок установки, таблица команд, состав поставки), `tools/host-runner/` (белый список целей),
  `Dockerfile` (закрепление версии OpenSpec мажорной, а не полной).
- Внешняя зависимость: доступность GHCR при запуске контейнера. Ранее установка требовала сети только на
  шаге загрузки поставки и сборки образа, теперь — ещё и при первом `make up`.
- Требуется публичная видимость пакета в GHCR: иначе установка в чужом проекте потребует аутентификации
  в реестре.
- Плановая пересборка меняет содержимое образа без коммита в репозиторий: тег остаётся прежним, состав
  инструментов обновляется. Это осознанный размен — свежие инструменты против побайтовой неизменности
  образа под одним тегом; неизменность обеспечивается адресацией по digest, а не тегом.
- Не затрагивается: блок бейджей `README.md` — значения по-прежнему читаются из `Dockerfile`, который
  остаётся в репозитории kit'а; механизм установки и манифест; изоляция профилей аккаунтов.
