## Why

Цель `make init` заявлена как подготовка проекта к запуску, но доводит до готовности только часть
окружения: создаёт `.env` из шаблона, каталоги `.ssh/` и `.claude-accounts/` и записи в `.gitignore`.
SSH-ключа в `.ssh/` после неё нет — есть только пустой каталог. Ключ и конфигурацию SSH пользователь
доносит вручную отдельным шагом README, копируя личный ключ хоста командой `cp`.

В результате подготовка расщеплена: часть выполняет цель `make`, часть — команды из инструкции.
Пользователь, прошедший `make init`, получает окружение, которое выглядит подготовленным, но push
из контейнера не проходит: ключа нет, а `.ssh/config` не создан, хотя пути к нему объявлены
в `.env.example` (`SSH_KEY`, `SSH_CONFIG`) и `.ssh/` монтируется в контейнер.

## What Changes

- Подготовительная цель начинает создавать SSH-ключ: пара ed25519 генерируется в каталоге `.ssh/`
  по пути из `SSH_KEY`. Ключ проекта самостоятельный — личный ключ хоста в проект не копируется.
- Ключ генерируется без passphrase: push из контейнера неинтерактивен, `ssh-agent` внутри
  контейнера не запускается, и ключ с passphrase сделал бы окружение неработоспособным.
- Подготовительная цель начинает создавать `.ssh/config` по пути из `SSH_CONFIG` с записью `Host`
  для `GIT_HOST`: `IdentityFile` из `SSH_KEY`, `User` из `GIT_USER`. Пути объявлены в `.env.example`,
  но файла до сих пор никто не создавал.
- Подготовительная цель остаётся идемпотентной: существующий ключ и существующий `.ssh/config`
  не перезаписываются и не изменяются — по тому же принципу, по которому не перезаписывается `.env`.
- Подготовительная цель выставляет права доступа на созданные файлы: `600` на приватный ключ,
  `644` на публичный ключ и `.ssh/config` — иначе SSH отказывается использовать ключ.
- Подготовительная цель сообщает, что делать дальше: показывает публичный ключ и указывает, что его
  необходимо добавить в git-сервис, — без этого push из контейнера не пройдёт.
- Порядок установки в `README.md` сокращается: ручное копирование ключа из шага «Положить SSH-ключ
  и создать профиль» уходит, в шаге остаётся создание каталога профиля и регистрация публичного
  ключа в git-сервисе.

### Modified Capabilities

- `kit-installation`: требование к операциям окружения описывает подготовительную цель как
  создающую файл секретов и каталоги; оно расширяется обязанностью довести SSH-доступ до рабочего
  состояния. К способности добавляются требования к генерации ключа, конфигурации SSH для
  git-хоста, правам доступа на созданные файлы и предъявлению публичного ключа пользователю.

## Impact

- `Makefile` — цель `init` расширяется генерацией ключа и созданием `.ssh/config`.
- `README.md` — раздел «Порядок установки», шаг 4: ручное копирование ключа заменяется указанием
  добавить сгенерированный публичный ключ в git-сервис.
- Зависимость: `ssh-keygen` (пакет `openssh-client`) на хосте. Цель выполняется на хосте, а не
  в контейнере, поэтому утилита должна быть в предусловиях установки наравне с `docker` и `make`.
- Ограничение: тип ключа фиксирован — ed25519. Выбор типа и длины ключа параметрами в объём
  не входит.
- Ограничение: регистрация публичного ключа в git-сервисе остаётся ручным шагом пользователя.
  Обращение к API git-сервиса в объём не входит.
- Ограничение: `known_hosts` в объём не входит — файл по-прежнему не создаётся, хотя путь к нему
  объявлен в `.env.example` (`SSH_KNOWN_HOSTS`).
- Ограничение: создание каталога профиля аккаунта `.claude-accounts/$CLAUDE_PROFILE` в объём
  не входит и остаётся ручным шагом.
- Допущение: сгенерированный ключ не защищён passphrase. Это осознанный размен: неинтерактивный
  push из контейнера против защиты приватного ключа на диске. Ключ лежит в `.ssh/`, который
  исключён из репозитория записью в `.gitignore`.
