# host-runner Specification

## Purpose

Описывает поведение host-runner — HTTP-сервиса на хосте, который по запросу из контейнера
выполняет одну из ограниченного набора целей `make` этого репозитория и возвращает её вывод,
не выдавая контейнеру доступ к Docker-сокету.

## Requirements

### Requirement: Белый список целей ограничен Makefile репозитория
Host-runner SHALL принимать к выполнению только цели `make` из белого списка, каждая из которых
существует в `Makefile` этого репозитория: `build`, `up`, `down`, `init`, `help`. Запрос любой
другой цели MUST завершаться отказом с кодом `400` и без выполнения `make`.

Белый список MUST быть подмножеством целей `Makefile`, а не совпадать с ними: цель, требующая
терминала для взаимодействия с пользователем, MUST NOT входить в белый список. Такая цель не
завершилась бы сама и удерживала бы host-runner до предела времени выполнения, блокируя все
последующие запросы.

#### Scenario: Разрешённая цель
- **WHEN** агент запрашивает цель `up`
- **THEN** host-runner выполняет `make up` в корне репозитория и возвращает код возврата и вывод

#### Scenario: Цель вне белого списка
- **WHEN** агент запрашивает цель, отсутствующую в `Makefile` репозитория (например `authors` или
  `restart`)
- **THEN** host-runner отклоняет запрос с кодом `400`, не запуская `make`, и перечисляет разрешённые
  цели в ответе

#### Scenario: Интерактивная цель Makefile
- **WHEN** агент запрашивает цель, которая существует в `Makefile`, но требует терминала
  (например `shell`)
- **THEN** host-runner отклоняет запрос с кодом `400`, не запуская `make`, и не удерживает
  соединение до предела времени выполнения

### Requirement: Выполнение цели без интерпретатора команд и без параметров
Host-runner SHALL выполнять цель `make` как список аргументов процесса, без shell-интерпретатора и
без пользовательских присваиваний переменных. Значение, переданное сверх имени цели, MUST NOT
попадать в команду `make`.

#### Scenario: Запрос с посторонними параметрами
- **WHEN** запрос содержит дополнительные параметры сверх имени цели
- **THEN** host-runner игнорирует их либо отклоняет запрос, но не подставляет их значения в команду
  `make`

### Requirement: Токен и однопоточное выполнение
Host-runner SHALL проверять общий секретный токен в заголовке каждого запроса и отклонять запрос
с неверным или отсутствующим токеном кодом `403`, не выполняя `make`. Host-runner SHALL выполнять
не более одной цели `make` одновременно.

#### Scenario: Неверный токен
- **WHEN** запрос приходит с неверным значением токена
- **THEN** host-runner отвечает кодом `403` и не выполняет `make`

#### Scenario: Параллельные запросы
- **WHEN** второй запрос приходит, пока выполняется цель по первому
- **THEN** второй запрос дожидается завершения первого — параллельного выполнения `make` не
  происходит
